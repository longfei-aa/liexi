# Rift Squad 中期项目书

## 1. 项目当前定位

《Rift Squad / 裂隙小队》当前已经从概念设计阶段推进到 Unreal Engine 5.6.1 C++ 可运行原型阶段。项目目标仍然保持不变：先完成一款 10-15 分钟、可重复游玩、后续可联机验证的合作肉鸽-like 动作 Demo，再逐步扩展为更完整的独立游戏。

当前版本不是商业级 Demo，也不是最终玩法形态，但已经具备最小可玩闭环：玩家可以进入灰盒场景、按键部署、战斗、清房、选择奖励、进入补给节点、挑战 Boss、胜利或失败，并在结算后重新开始。

## 3. 当前可演示效果

当前打开项目后，进入 `/Game/RiftSquad/Maps/M_Greybox_CombatRoom`，点击 Play，会先显示部署提示。按 `Enter` 后开始一局 Demo。

玩家可以：

- 使用 `WASD` 移动。
- 使用鼠标瞄准。
- 使用左键射击。
- 使用 `Q / 右键` 释放冲击波。
- 使用 `Space` 闪避。
- 清理房间敌人。
- 使用 `1 / 2 / 3` 选择奖励或补给。
- 挑战最终 Boss。
- 在胜利或失败后按 `Enter` 重新开始。

当前 Demo 已经可以用于展示核心玩法方向：短局制、战斗清房、随机成长、Boss 前补给、结算重开。

## 4. 后续是否会调整已有内容

后续会继续调整已有内容，但不会推翻当前方向。当前版本的主要价值是验证玩法和技术闭环，后续调整重点是把临时实现逐步升级为可扩展、可联机、可打包的 Demo 结构。

预计会调整的内容：

- Canvas HUD 后续会逐步替换为 UMG UI。
- 当前几何体占位模型会逐步替换为免费或开源素材。
- 当前硬编码道具池会迁移到 DataAsset 或 DataTable。
- 当前线性 5 房间流程会扩展为房间模板池和随机路线。
- 当前 Boss 只是强化敌人形态，后续会改成真正多阶段 Boss。
- 当前联机接口有基础服务端权威路径，但仍需要完整双客户端验证和大厅流程。
- 当前敌人 AI 仍偏原型，后续会拆分更多行为、前摇、反馈和数值表。

## 5. 后续开发大阶段

### 阶段一：Demo 表层体验与菜单流程

目标：让当前原型从“编辑器里能玩”升级为“非开发者也能理解如何开始”。

开发内容：

- 制作 UMG 主菜单。
- 加入 `Start Demo`、`Host Game`、`Join Game`、`Settings`、`Quit` 的基本结构。
- 将当前 Canvas 部署提示逐步迁移到 UMG。
- 制作暂停菜单和返回主菜单流程。
- 加入基础设置项：音量、窗口模式、鼠标灵敏度。
- 优化 HUD 信息层级，减少调试感。

阶段验收：

- 打开游戏后先进入主菜单。
- 玩家能从菜单进入当前战斗 Demo。
- 结算后能返回菜单或重新开始。

### 阶段二：联机验证与好友房间

目标：完成 2 人 Listen Server 联机验证，使项目真正符合合作游戏方向。

开发内容：

- 使用 UE PIE 双客户端验证当前流程。
- 验证玩家移动、射击、技能、闪避同步。
- 验证敌人生成、受击、死亡同步。
- 验证奖励选择、补给选择、房间推进同步。
- 验证胜利、失败、重开同步。
- 增加简单 Host / Join 流程。
- 记录联机测试用例和已知问题。

阶段验收：

- 两个客户端可以进入同一局。
- 房主和客户端看到的房间进度、敌人状态、奖励选择基本一致。
- 两名玩家可以一起完成一局或失败重开。

### 阶段三：内容数据化与随机房间

目标：把当前线性 Demo 升级为可扩展的肉鸽-like 框架。

开发内容：

- 将道具池从 C++ 临时数组迁移到 DataAsset 或 DataTable。
- 将敌人数值、房间配置、奖励权重数据化。
- 建立房间模板池。
- 实现普通房、精英房、补给房、Boss 房的节点生成。
- 加入基础路线随机逻辑。
- 加入每局随机奖励池和房间威胁值控制。

阶段验收：

- 每一局的房间组合和奖励选择有变化。
- 策划可以通过数据文件调整道具、敌人、房间配置。
- 不需要频繁改 C++ 就能扩展内容。

### 阶段四：美术音频与战斗手感打磨

目标：从灰盒原型升级为可展示的视觉和听觉 Demo。

开发内容：

- 引入免费或开源低多边形 / 科幻 / 简化角色素材。
- 替换玩家、敌人、子弹、场景占位模型。
- 加入射击、命中、死亡、奖励、胜利、失败音效。
- 加入命中闪光、爆炸、冲击波、奖励拾取等 VFX。
- 加入屏幕震动、受击提示、危险区域提示。
- 统一色彩风格和 UI 视觉风格。
- 记录所有第三方素材来源和许可证。

阶段验收：

- Demo 不再明显像纯灰盒工程。
- 玩家能清楚感受到命中、受击、奖励、失败、胜利。
- 所有引入素材都有来源记录。

### 阶段五：可试玩 Demo 打包与发布准备

目标：形成可以发给朋友测试的本地试玩版本。

开发内容：

- 完成 Mac / Windows 打包验证。
- 清理调试信息和临时文案。
- 建立试玩测试清单。
- 建立 Bug 记录模板。
- 增加基础性能检查。
- 完成 Demo 操作说明。
- 准备版本号和发布说明。

阶段验收：

- 非开发者可以下载、启动、进入菜单、开始 Demo、完成一局或失败重开。
- 至少完成一次 2 人联机试玩测试。
- 有明确的已知问题列表和下一版本计划。

## 6. 当前风险与注意事项

- 联机仍是最大技术风险，需要尽早做双客户端验证。
- 当前素材仍是占位状态，视觉完成度距离公开展示还有差距。
- 当前 Boss 机制较弱，需要在后续阶段重点加强。
- 当前系统仍有硬编码内容，内容扩展前必须数据化。
- 当前 UI 是原型实现，后续迁移 UMG 时需要避免一次性大改导致回归。

## 7. 下一步建议

下一步优先级建议：

1. 先做 UMG 主菜单雏形，补齐 Start / Host / Join / Quit 的项目入口。
2. 随后做 PIE 双客户端联机验证，记录同步问题。
3. 再推进道具、敌人、房间配置数据化。

这个顺序更稳：先让 Demo 看起来像一个游戏入口，再验证它是否能联机，然后再扩展内容。
